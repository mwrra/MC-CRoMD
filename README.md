# MC-CRoMD

**MC-CRoMD: A Multi-Channel Statistical Feature Extraction and Selection Framework for Lung and Colon Histopathological Image Classification Using Machine and Deep Learning**

This repository provides the implementation code, selected validation results, final locked-test results, and publication figures for the revised MC-CRoMD study.

## Overview

MC-CRoMD is a statistical feature-extraction and selection framework for lung and colon histopathological image classification.

Each image is divided into non-overlapping patches. For each patch, the framework computes Cronbach's Alpha as a heuristic inter-channel descriptor across the RGB channels together with eight channel-wise statistical measures:

* Range
* Variance
* Standard Deviation
* Q1
* Q3
* Interquartile Range
* Mean Absolute Deviation
* Coefficient of Variation

Each patch therefore produces 25 statistical features.

Four patch sizes are evaluated:

* 32×32
* 64×64
* 128×128
* 256×256

Three classification tasks are considered:

* Binary colon classification
* Three-class lung classification
* Five-class lung and colon classification

## Dataset

The experiments use the **LC25000 Lung and Colon Histopathological Image Dataset**, which contains 25,000 color histopathological images distributed across five classes.

The LC25000 images are not redistributed in this repository.

The dataset used in this study was downloaded from Kaggle:

* **Dataset used in this study:**
  https://www.kaggle.com/datasets/andrewmvd/lung-and-colon-cancer-histopathological-images

The original LC25000 dataset archive is available from:

* **Original dataset archive:**
  https://academictorrents.com/details/7a638ed187a6180fd6e464b3666a6ea0499af4af

The dataset was introduced in:

* Borkowski, A. A., Bui, M. M., Thomas, L. B., Wilson, C. P., DeLand, L. A., & Mastorides, S. M.
  *Lung and Colon Cancer Histopathological Image Dataset (LC25000).*
  arXiv:1912.12142
  https://arxiv.org/abs/1912.12142v1

Users who wish to reproduce the experiments should obtain LC25000 from an authorized source and preserve its original class organization before running the MC-CRoMD workflow.

### LC25000 Augmentation-Group Information

LC25000 was generated by applying image transformations to a smaller set of original tissue images. Consequently, multiple augmented images may originate from the same underlying source image.

To reduce augmentation-related data leakage, the revised MC-CRoMD workflow groups images originating from the same source before constructing the training, validation, and independent test partitions.

The identification and organization of augmentation-related image groups were informed by the **LC25000-clean** resource introduced by Batchkala, Li, and Rittscher:

* **LC25000-clean repository:**
  https://github.com/GeorgeBatch/LC25000-clean

* **Associated study:**
  George Batchkala, Bin Li, and Jens Rittscher.
  *Evaluating Histopathology Foundation Models for Few-shot Tissue Clustering: an Application to LC25000 Augmented Dataset Cleaning.*

The LC25000-clean resource provides clustering labels and a semi-automatic annotation pipeline designed to group augmented images originating from the same prototype.

## Data Partitioning and Leakage Control

A fixed **source-group-aware** partitioning strategy is used throughout the revised experiments.

The approximate partition proportions are:

* Training: 72%
* Validation: 8%
* Locked independent test: 20%

Images belonging to the same source group are assigned to the same partition. Therefore, augmentation-related images originating from the same source are not intentionally distributed across training, validation, and test partitions.

The reference split assignments are propagated across the evaluated patch sizes so that the experiments remain comparable.

The experimental policy follows these rules:

1. Preprocessing parameters are fitted using the training partition only.
2. Feature-selection procedures are fitted using the training partition only.
3. The validation partition is used for model comparison, configuration selection, and hyperparameter tuning.
4. The independent test partition remains locked throughout model development.
5. Machine-learning and DNN configurations are finalized before the locked test partition is evaluated.
6. The locked independent test partition is used only for final evaluation.

The exact training and validation sample counts associated with individual experiments are recorded in the validation result files provided in the repository.

## Feature Selection

Six feature-selection methods are evaluated together with the complete-feature baseline (`AllMsr`):

* Chi2
* Fclass
* Mutclass
* Variance
* Random Forest
* Logistic Regression
* AllMsr baseline

Feature-selection procedures are fitted using training data only.

The validation result files in:

`results/validation/ML/`

and

`results/validation/DNN/`

provide compact summaries of the evaluated configurations.

The `Best_Configuration_Per_Scenario` files identify, for each classification scenario, information including:

* Feature-selection method (`Feature_Method`)
* Number of retained features (`K`)
* Selected model or DNN configuration
* Validation performance

Full selected-feature matrices are not redistributed in this repository in order to keep the repository compact. The feature-selection procedures and their configuration remain traceable through the source code and validation result files.

## Classification Models

Nine conventional machine-learning models are evaluated:

* SVM with RBF kernel
* SVM with polynomial kernel
* K-Nearest Neighbors
* Random Forest
* Decision Tree
* Logistic Regression
* SGD Classifier
* Gaussian Naive Bayes
* Voting Classifier

A fully connected Deep Neural Network is also evaluated using the MC-CRoMD statistical feature vectors.

## Validation and Model Selection

Machine-learning and DNN validation results are maintained separately.

### Machine Learning

Validation summaries are available in:

`results/validation/ML/`

For each patch size, the repository provides:

* Best configuration per classification scenario
* Compact validation-results summary

### Deep Neural Network

DNN validation summaries are available in:

`results/validation/DNN/`

For each patch size, the repository provides:

* Best DNN configuration per classification scenario
* Compact DNN validation summary

The four evaluated patch sizes are represented in both validation directories:

* 32×32
* 64×64
* 128×128
* 256×256

Model and configuration selection is based on validation performance and is completed before final locked-test evaluation.

---

## Final Locked-Test Evaluation

The independent test partition is not used during preprocessing, feature selection, model selection, or hyperparameter tuning.

After validation is completed, the selected machine-learning and DNN configurations are frozen and subsequently evaluated on the locked independent test partition.

Final results are provided separately in:

`results/final_ml/`

and

`results/final_dnn/`

The repository includes selected final result files rather than every intermediate execution artifact in order to keep the repository compact while preserving the information required to verify the reported final results.

The provided final results include the principal evaluation metrics with 95% confidence intervals and the confusion-matrix counts used for final reporting.

## Reproducibility

The repository contains the principal scripts required to reproduce the MC-CRoMD experimental workflow.

These scripts cover:

* Statistical feature extraction
* Source-group-aware data partitioning
* Propagation of the reference split across patch sizes
* Data-quality auditing
* Data preprocessing
* Feature selection
* Machine-learning screening
* Machine-learning hyperparameter tuning
* DNN validation
* Final locked-test evaluation
* Publication figure generation

Software dependencies are listed in:

`requirements.txt`

Fixed random seeds and experiment parameters are recorded in the corresponding scripts and result files where applicable.

The principal execution order is:

`Pre1 → Pre2 → Pre2B → Pre3 → Pre4 → Pre5 → Pre6 → Pre7 → Publication Figures`

where:

* `Pre1` performs MC-CRoMD feature extraction.
* `Pre2` constructs the source-group-aware reference split.
* `Pre2B` propagates the reference split to the other patch sizes.
* `Pre3` performs data-quality auditing.
* `Pre4` performs data preprocessing.
* `Pre5` performs feature selection.
* `Pre6` performs machine-learning and DNN validation/model selection.
* `Pre7` performs final locked-test evaluation.
* `Generate_Final_Publication_Figures.py` generates the final publication figures from saved outputs.

The test partition is not required for model-development stages and remains locked until final evaluation.

Because the original LC25000 dataset and large intermediate feature matrices are not redistributed, users must first obtain and prepare the dataset before executing the complete workflow.

## Results

The `results/` directory contains selected validation and final locked-test outputs.

The results are organized as follows:

```text
results/
├── validation/
│   ├── ML/
│   └── DNN/
├── final_ml/
└── final_dnn/
```

Validation results provide the compact information required to trace how the final configurations were selected.

Final-test directories contain selected outputs from the locked independent test evaluation.

Intermediate checkpoints, temporary files, progress files, complete bootstrap distributions, and other execution-specific artifacts are intentionally not redistributed in order to keep the repository concise.

---

## Figures

The `figures/` directory contains final publication figures generated from saved validation and locked-test outputs.

The included figures show:

* DNN validation-loss trajectories
* Final locked-test confusion matrices using exact sample counts
* Final locked-test confusion matrices using row-normalized percentages

The corresponding figure-generation program is provided in the `code/` directory:

`Generate_Final_Publication_Figures.py`

The figure-generation script performs visualization of previously saved results and does not retrain, tune, rank, or select models.
